# IR情報の信頼性監査・独立情報源の追加（2026-09-21）

## 到達点

**EDINETとそれ以外の寄与を同程度にする目標は未達。**
件数を合わせるために確認基準を緩めたり、既存の正しいEDINET関係を間引いたりはしていない。

集計対象は、全体図に載せられる上場企業間の `confirmed` 関係。同じ企業対・関係タイプは一つに統合し、同じ情報源のURLや根拠が複数あっても1件と数える。両方の裏付けがある関係は重複区分として明示する。公表資料に記載された時点の関係であり、現在までの継続を一律に保証するものではない。

| 指標 | 監査前の集計 | 今回の集計 |
|---|---:|---:|
| EDINETの裏付けあり | 10,851 | 10,468 |
| EDINET以外の裏付けあり | 253 | 1,411 |
| 両方の裏付けあり | 97 | 904 |
| EDINETのみ | 10,754 | 9,564 |
| EDINET以外のみ | 156 | 507 |

現在の「その他 / EDINET」は **13.5%**。同数までは9,057件分の差がある。
監査前は有報転載を独立資料と区別していなかったため、単純な追加件数だけの比較ではない。
非上場を含む全関係ではEDINET 87,636件、その他3,467件、両方1,506件。

## IR抽出の監査

従来のIR抽出3,642行、参照URL1,498件を取得して本文照合した。

| 本文照合 | 行数 |
|---|---:|
| 正規化後の抽出根拠文字列を確認 | 1,149 |
| 文字列を確認できず | 2,417 |
| 取得失敗 | 39 |
| 根拠が短すぎる | 37 |

空白・句読点・文字幅を正規化した照合である。不一致は要約、ページ更新、PDF抽出の限界でも起こるため、捏造や関係不存在を意味しない。一致しても当事者、関係分類、方向、現在の継続、サイト運営者の同一性を保証しない。

本文照合と従来の意味・方向のルールを両方通過したIR行は389行。取り込み対象3,568行のうち3,179行は要確認。複数行が同一関係に統合されるため、行数は関係数ではない。

修正した問題：

- 本文で確認できない抽出根拠は、単独で関係を確定させない。
- 英文社名の先頭語が同じだけで別法人を同一視しない。
- 日本語の濁点・半濁点を保持し、「プラス／ブラス」「エヌビーシー／エヌピーシー」を別名として扱う。既存EDINET関係の件数にもこの照合修正が反映されている。
- 有限会社・合同会社等を、同名の上場株式会社に自動統合しない。
- 製品採用・納入だけでは「連結売上10%以上の主要販売先」と判定しない。
- 合弁出資の出資先と共同出資者を混同しない。従来のIR抽出では対象法人の裏付けが不足するものを要確認にする。
- EDINETの役員兼任にも確認を適用し、顧問・相談役など両社の役員職を確認できない334関係を要確認にする。
- 同じURLに不一致の抜粋と一致する抜粋がある場合、重複排除によって一致の根拠が失われないようにする。
- 企業サイトに掲載された有価証券報告書は `origin: edinet_republication` とし、寄与度ではEDINETに含める。

出典種別と抽出内容の信頼性は別に扱う。画面には本文照合、照合日、AIによる個別照合、根拠単位の要確認を表示する。原文の引用部分は公開JSONに含めない。

## 追加した情報

最初の調査では1,792社のURL候補を調査し、1,672社から計10,555ページを取得。その後、追加の役員・株主ページと公式ニュースを調査中。URL候補はWikidataの公式サイト項目を入口にしたが、それだけで正しい企業サイト・関係とは判定しない。

企業公式サイト・発表資料から1,313件の確認記録を追加した。これは重複関係の裏付けも含む出典記録数であり、新規エッジ1,313本という意味ではない。

- 株主表：385記録。表の当事者と基準日を確認し、記名株主として取り込む。比率の定義が不明な数値を既存値に上書きしない。
- 役員紹介：537記録。人物と現在の兼職を個別に照合した420記録と、同じ資料・人物・時点の確認済み役職から生成した117記録。略歴に社名が出るだけの退任者は採用しない。
- 公式取引先一覧：264記録。新タイプ「取引先（公式掲載）」で表し、売買の方向・売上10%以上・継続取引を推定しない。同じ企業対に確認済みの取引関係がある場合は重複追加を避けた。
- 主要仕入先：17記録。公式サイトの明示的な仕入先一覧を根拠にする。
- 提携・共同開発等：110記録。上場親会社が発表していても、実際の当事者が子会社なら子会社のまま記録する。合意・予定と実行済みを区別する。

具体例：

- [サーバーワークス・G-genとBIPROGYの業務提携](https://www.serverworks.co.jp/news/20260907_swx_g-gen_biprogy.html)
- [FRONTEOとカイオムの共同研究](https://www.fronteo.com/news/pr/20260903?hsLang=ja)
- [アイシンと日本電子の共同開発](https://www.aisin.com/jp/news/2026/010693.html)
- [BASEとSBIホールディングスの資本業務提携](https://binc.jp/press-room/news/press-release/pr_20260828)
- [ソルヴィーとジャックスの資本業務提携](https://solvvy.co.jp/news/20260915-3/)

すべてのURL、資料のハッシュ（取得できたもの）、日付、照合者、関係の当事者は `data_raw/official_relations.json` に保存。個別照合者は `codex_primary_source_review`、確認済み役職からの生成は `reviewed_same_document_offices` であり、人間による確認と称していない。

## 調べた追加情報源と採用上の条件

| 情報源 | 信頼できる範囲・今回の扱い |
|---|---|
| 企業公式の株主表・役員紹介・会社概要 | 当該企業が公表した事実の一次資料。法人・時点・役職・表の意味を照合して採用。更新日不明は不明のまま表示 |
| 企業公式プレスリリース | 当事者による発表の一次資料。親子の混同、予定の実行済み扱い、第三者同士の記述を除外して採用 |
| [NEDO](https://www.nedo.go.jp/)・[JSTの発表](https://www.jst.go.jp/pr/press-2025.html) | 採択・研究実施の一次資料。大きな事業やコンソーシアムの参加企業同士をすべて直接提携の線で結ぶことはしない。今回の確定データには未追加 |
| [特許庁の公報データ](https://www.jpo.go.jp/system/laws/sesaku/data/download.html) | 出願等の事実に適する。大量データの取得手続、法人識別、関係の時点の検証が別途必要。今回未追加 |
| [USPTO PatentsView](https://www.uspto.gov/ip-policy/economic-research/patentsview) | USPTOの研究用加工データで、公式原簿そのものではない。現在の提携や現在の権利者を直接示すものではない |
| [PatentsViewの2024年末版アーカイブ](https://zenodo.org/records/15783125) | 出願人データ6,010,194行を試験分析。現在の企業英文名との厳密な正規化一致で208企業対の候補。ただし同名法人・旧社名・権利移転・年代・アーカイブの由来の追加検証が必要。候補を確定関係に取り込んでいない |

特許候補を現在の業務提携に読み替えたり、同一事業の参加者から無条件に企業対を作って寄与度を水増ししたりはしない。IR候補と役員紹介にも未確認のものが残っている。

## 再現方法

追加依存は `requirements-audit.txt`。取得本文・PDF・引用部分・候補一覧は無視対象の `outputs/` に保存し、Git管理するのは事実と検証メタデータのみ。

```sh
python pipeline/audit_ir_sources.py --out outputs/ir-source-audit --checks-out pipeline/data_raw/ir_source_checks.json
python pipeline/discover_issuer_sources.py --out outputs/issuer-source-research
python pipeline/build_masters.py
python pipeline/make_viz_data.py
python pipeline/source_contribution.py pipeline/data_processed/masters/M5_company_relations.json
python3 -m unittest discover -s pipeline/tests
npm test
npm run build
```

`discover_issuer_sources.py` は候補発見用であり、自動承認や無人での件数目標達成を行うものではない。基準を満たした事実だけを `official_relations.json` に追加して再生成する。
